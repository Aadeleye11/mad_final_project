# RwandaGo

An offline-first Rwanda travel companion built with Flutter. Travellers browse
attractions, build a day-by-day itinerary around their interests, and carry it
with them as a QR code, with no connectivity required once it's generated.

University final project (group coursework), graded against a rubric that
targets Android/iOS only.

## Features

- **Discover:** browse attractions in a responsive grid, search by name,
  district or category, filter by category, and view a full detail page
  (rating, best day to visit, local tips, directions, share). Data loads from
  Firestore when online and falls back to a local cache, then to a bundled
  seed file, so the catalogue always has something to show.
- **Plan:** generate a day-by-day itinerary from your saved interests, then
  add, edit, reorder or remove activities per day, either from the Discover
  catalogue or as free text. Trip edits sync to Firestore and mirror to local
  storage so the plan keeps working offline.
- **Home:** a dashboard with a greeting, trip summary (activities booked,
  days, home city), and featured spots pulled from the same Discover
  catalogue.
- **QR sharing:** encodes the active itinerary into a QR code that can be
  scanned and read with no internet connection.
- **Profile:** edit display name, bio, phone, home city and avatar; review
  saved itineraries; inspect and clear the offline attraction cache; log out.
- **Auth:** email/password sign up and login.

## Tech stack

- **Flutter** (Dart ^3.12): see [pubspec.yaml](pubspec.yaml) for the full
  dependency list
- **State management:** [flutter_bloc](https://pub.dev/packages/flutter_bloc)
  (BLoC pattern) throughout
- **Dependency injection:** [get_it](https://pub.dev/packages/get_it) for the
  Discover feature's service locator
- **Backend:** Firebase Auth + Cloud Firestore
- **Local persistence:** `shared_preferences` (profile, interests, itinerary
  mirror, attraction cache)
- **Error handling:** `dartz`'s `Either<Failure, T>` in the Discover feature's
  repository layer
- Notable packages: `cached_network_image`, `image_picker`, `qr_flutter`,
  `mobile_scanner`, `share_plus`, `url_launcher`, `connectivity_plus`

## Architecture

The codebase is mid-migration from a flat MVC-ish layout to a
Clean-Architecture, vertical-slice structure. The **Discover** feature is
fully migrated and is the reference pattern for new work:

```
lib/
├── main.dart                    shared app entrypoint & DI wiring
├── injection_container.dart     shared get_it registrations
├── firebase_options.dart        generated by FlutterFire CLI
├── core/                        shared: theme, colors, failures, usecase base
├── features/
│   └── discover/                data / domain / presentation, fully sliced
├── data/                        legacy: models & repositories (auth, plan, profile)
├── logic/blocs/                 legacy: BLoCs (auth, home, interests, plan, profile)
└── presentation/screens/        legacy: screens for auth, home, plan, profile
```

Within `features/discover/`, dependency direction is strictly inward
(`presentation → domain ← data`) and the domain layer has no Flutter or
Firebase imports, so it's cheap to unit test.

Three people work on this repo. To keep merge conflicts down, ownership is
split by folder:

| Path | Scope |
|---|---|
| `lib/features/discover/**` | Discover feature |
| `lib/logic/blocs/plan/**`, `lib/presentation/screens/plan/**` | Plan/trips |
| `lib/logic/blocs/auth/**`, `lib/presentation/screens/auth/**`, `lib/data/repositories/auth_repository.dart` | Auth |
| `lib/core/**`, `main.dart`, `injection_container.dart` | Shared, touch only for a feature's own registration line |

## Getting started

**Prerequisites:** Flutter SDK (channel stable, Dart ^3.12), an Android
emulator or iOS simulator, and the Firebase config files
(`android/app/google-services.json`, `ios/Runner/GoogleService-Info.plist`),
already checked into this repo, no `flutterfire configure` needed for a fresh
clone.

```bash
flutter pub get
flutter run                 # pick a connected device or emulator
```

> Android/iOS only. A web or desktop build is out of scope for this
> project's rubric and Firebase is not configured for those platforms.

## Testing & quality

```bash
dart format .
flutter analyze              # must report 0 issues before committing
flutter test                 # widget, BLoC and unit tests
flutter test --coverage
```

Test suite covers: the Discover BLoC and its widgets, the Plan and Profile
BLoCs, the itinerary generator service, and an end-to-end widget flow from
splash through login, onboarding, home, plan and QR.
